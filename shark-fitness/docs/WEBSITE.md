# Public website

The gym's public website: `apps/website` (`@shark/website`), a static [Astro](https://astro.build) site served by the API process at `/` on the same origin as the member app (`/app/`) and the staff console (`/admin/`). It needs no server of its own and works without the API: plans, branches and the timetable are built in, then refreshed live in the browser when the API answers.

## Pages

| Path | Page | Notes |

## Editing content

- **What the gym's system holds** (branches, hours, holidays, amenities, contact details, published plans and prices, the class timetable) lives in `src/content/snapshot.json`. Do not edit it by hand. Change the data in the console, then refresh the file from a running API and rebuild:

  ```bash
  pnpm -F @shark/website sync-content -- --api https://pilot.example.com   # or http://localhost:8787
  pnpm -F @shark/website build
  ```

  `--tenant <slug>` picks another gym (default `SHARK_SITE_TENANT`, else `shark`). The script reads only the public endpoints.
- **Everything else** (postcodes and map positions, the "getting there" and "on the floor" lists, coach profiles, class descriptions, what each plan is best for, FAQs, form options) is typed in `src/content/site.ts`. TypeScript checks it at build.
- **Which plans appear**: in the console, Plans → "Show on website" on each plan. Only *active* plans are listed, and only at branches where they are sold. A new or duplicated plan starts unpublished.
- **Privacy notice**: when `src/pages/privacy.astro` changes, raise `PRIVACY_NOTICE_VERSION` in `src/content/site.ts`. Every enquiry stores the version the person saw.
- **Open Graph image**: `public/og.png` (1200×630) is generated by `pnpm -F @shark/website og-image` and committed. Rerun it when the headline or branches change.
- **Photography**: there is none yet. The design uses the Sonar graphic language (contours, hairline seams) instead. When real photos exist, the natural slots are the home hero (right of the headline, replacing the contour graphic), each location page's hero, and the coach cards. Use AVIF/WebP with explicit `width`/`height` so the layout does not shift.

## Forms and leads

Both forms post to the public API (`/v1/public/<tenant>/trial-requests` and `/leads`). The page validates first and announces errors (an `aria-live` summary, each error tied to its field) and moves focus to the first problem; the API is the authority and its field errors are shown the same way.

What the API does with a submission:

- normalises the phone to E.164 (default +91) and deduplicates by phone or email: a known person gets a note on their existing lead, a lost lead is reopened, and a converted member is linked to their member record rather than duplicated;
- records source `website`, the campaign (first touch; UTM from QR codes and ads is kept for the visit in `sessionStorage`), any referral code, and the consent given with the notice version;
- for trial requests, records the requested class or time and gives staff a call-back deadline two hours after the branch next opens, which drives the Leads board's "overdue" flag;
- never books a class, holds a seat, or sends the visitor anything. The page says the team will call.

Staff see these leads under Leads → Source "Website", with a "trial requested" chip and the campaign. Lead detail → Free trial → "Confirm trial" records the agreed class and moves the lead to *trial booked*.

Abuse controls: a hidden honeypot field and a minimum fill time of three seconds (both answered with the same 202 and nothing stored), five submissions per IP per ten minutes per form, a per-gym hourly budget, a known `Origin`, a 16 KB body cap and `Idempotency-Key` support. Unknown and suspended gyms get the same 404.

**QR campaign links**: print `https://<domain>/?utm_source=qr&utm_medium=poster&utm_campaign=<name>` (any page works). The campaign shows on the lead.

## Build-time settings

Read when `astro build` runs (the Docker image passes them as build args; the pilot's `compose.yaml` sets `SITE_URL` from `SHARK_DOMAIN` and `SITE_INDEXABLE` from `shark.env`).

| Variable | Default | Effect |
|---|---|---|
| `SITE_URL` | `https://www.sharkfitness.example` | Origin for canonical URLs, Open Graph URLs and the sitemap. Set to the real public origin. |
| `SITE_INDEXABLE` | `false` | Only `true` lets search engines index the site: robots meta `index, follow` and a `robots.txt` that allows crawling and names the sitemap. Anything else gives `noindex, nofollow` everywhere and `Disallow: /`. Keep it off on demos and staging. |
| `SHARK_SITE_TENANT` | `shark` | The gym slug the live parts and the forms use. |
| `SITE_ANALYTICS_SRC`, `SITE_ANALYTICS_DOMAIN` | empty | Optional analytics script (for example self-hosted Plausible). Off by default; nothing third-party loads otherwise. Adding one means updating the privacy notice. |
| `SHARK_API_URL` | `http://localhost:8787` | Development only: where `astro dev` proxies `/v1`, and the default for `sync-content`. |

## SEO

Every page has a unique title and description, a canonical URL, Open Graph and Twitter card tags (with `og.png`), and JSON-LD: `Organization` and one `ExerciseGym` per branch (address, geo, `openingHoursSpecification`, telephone, amenities) on Home and Locations, `OfferCatalog`/`Offer` (GST included) on Plans, `FAQPage` on FAQ and `BreadcrumbList` on inner pages. `/sitemap.xml` lists every indexable page; the 404 page is always `noindex`. `src/built-site.test.ts` checks all of this against the built output.

## Performance and budgets

The site ships no framework runtime. Each page's CSS is inlined; fonts are self-hosted Latin subsets (Anton, Archivo 400/600, Archivo Narrow 600) with the two used above the fold preloaded and `font-display: swap`; a Latin-extended subset carries ₹ and loads only where a rupee sign is printed. The build writes Brotli and gzip copies that the API serves directly. Hashed assets under `/_astro/` are cached for a year; HTML, `robots.txt`, the sitemap and `/sw.js` are revalidated on every request.

Budgets (checked by `src/built-site.test.ts` on every `pnpm test` after a build):

| Budget | Limit | Current |
|---|---|---|
| JavaScript per content page | ≤ 20 KB gzip | about 1–2 KB |
| JavaScript on Free trial / Contact | ≤ 35 KB gzip | about 4 KB |
| Lighthouse (mobile, simulated throttling) Home, Plans, Free trial | Performance ≥ 95, Accessibility ≥ 95, Best Practices ≥ 95, SEO = 100 | see the P03 PR |
| Cumulative Layout Shift | < 0.05 | 0 |

Lighthouse needs an indexable build served from its own origin (a `noindex` page cannot score 100 for SEO):

```bash
SITE_URL=http://localhost:18404 SITE_INDEXABLE=true pnpm -F @shark/website build
# start the production server on 18404 (README, "Production single-origin smoke"), then:
CHROME_PATH=/usr/bin/google-chrome pnpm dlx lighthouse http://localhost:18404/ --form-factor=mobile --throttling-method=simulate --output=json --output-path=home.json --chrome-flags="--headless=new"
```

## The move of the member app to `/app/`

The member app used to be served at `/`. Since this website took `/`:

- the member app builds with `base: '/app/'`, router basepath `/app`, manifest `id`/`scope`/`start_url` `/app/`, and a service worker scoped to `/app/`;
- console activation and recovery links for members point at `/app/sign-in#…`;
- the API redirects the old member paths (`/sign-in`, `/book`, `/pass`, `/workout/…`, …) to `/app/…`, keeping the query; browsers keep the `#fragment`;
- `/` forwards old `#activationId=`/`#recoveryId=` fragments and standalone launches to `/app/`;
- `/sw.js` is a self-unregistering worker: a phone that installed the old app gets it on its next visit, which deletes the old worker's caches (never `/app/`'s), unregisters it and reloads. Every website page also unregisters any worker scoped to `/` as it loads.

Installed home-screen apps from before the move keep working through these forwards, but members should reinstall from `/app/` to get the new icon and scope.

## Development

```bash
pnpm dev                         # API :8787, member :5173 (/app/), console :5174 (/admin/), website :5175
pnpm -F @shark/website dev       # website alone; /v1 proxied to SHARK_API_URL
pnpm -F @shark/website build     # astro check + build + precompress
pnpm -F @shark/website test      # form logic, and the built-site checks if dist/ exists
```
