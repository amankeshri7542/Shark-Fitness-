## Decisions

(Also copied to the PR.)

- **D1 Pass tokens.** `/v1/member/pass` returns a short run (6) of 30 s single-use codes with `no-store`; the client rotates early (before the window ends) and re-fetches the run. QR via pinned `uqr` (ECC M, 4-module quiet zone), dark on a light panel in both themes.
- **D2 Scan "already checked in".** A valid code from a member already inside (open visit) returns outcome `already_checked_in` with no second check-in row; the code window is still burned. Expired codes return `denied_token_expired` (separate from forged `denied_token_invalid`); a code minted by another tenant returns `denied_wrong_tenant` and names nobody.
- **D3 Decoder.** BarcodeDetector where available, else `jsqr@1.4.0` loaded by dynamic import only when the camera starts.
- **D4 Waitlist hold = seat.** An offer increments `class_sessions.booked`; accept converts without incrementing; decline/expiry/withdrawal decrements and re-offers. DB triggers count live bookings + live offers; the counter guard refuses only increases past capacity (so a shrunk class can still give seats back).
- **D5 Offer timing (decision 12).** Deadline = min(now + `waitlistOfferMinutes` (30), start − `waitlistOfferCutoffMinutes` (60)); both are branch-overridable policies. If less than a minute would remain, no offer is made and the freed seat is open to anyone (members waiting keep their place; first-come after the cut-off).
- **D6 No-show release.** No-shows are marked after class start, which is always past the offer cut-off, so marking a no-show does not create an offer (it would be unusable). Releasing a booking before class from the roster (`releaseBooking`) is the "release" path and does offer the seat. Recorded rather than building a dead path.
- **D7 Skipped members.** A member who is no longer eligible when their turn comes is moved to a new `skipped` state (added to `WaitlistState`), with the reason audited and an in-app note; they can rejoin (back of the line).
- **D8 Capacity reduction.** Allowed below bookings; cancels nobody. Live offers that no longer fit are withdrawn newest-first and those members return to `waiting` at their original position. Remaining excess → audit `session.overbooked`, realtime `alert.raised`, and a derived dashboard alert `overbooked_class` that stays until resolved. Two phase-5 tests that asserted the old refusal / "no offer" behaviour were rewritten to the decided behaviour (requirement change, not weakened).
- **D9 Leaving the line** marks the entry `declined` instead of deleting it (auditable history); rejoining reuses the row (`waitlist_uq`) at the back of the line.
- **D10 Credit lots.** Each pack's grant row is a lot; every spend/restore/refund row carries `lot_id` (+ `pack_id` on grants). Balance = pure replay (`@shark/domain` `creditLots`). Legacy rows without a lot: spends are applied to lots usable on that day (earliest expiry first); any shortfall is shown as a warning, never forgiven. A booking whose spend predates the ledger (seed/legacy) gets its units back without expiry on a timely cancel, as before.
- **D11 Allocation.** Inside `settleInvoicePayment` (the one settlement path for desk, Checkout confirm, webhook and reconciliation) once `paidMinor >= totalMinor`; a failed grant rolls the payment back (tested). Free packs allocate at sale.
- **D12 Forfeit policy.** Late cancellation and no-show forfeit the credit for every pack (existing `classifyCancellation`); no per-product override was added (nobody asked for one).
- **D13 Refund matrix (decision 11).** Unused & unexpired → everything paid; partly used → unused × floor(price ÷ units), reason required; expired → refused; nothing left → refused. Refund goes back to the newest single payment that can carry it; a pack paid in several parts is refused with a plain message (rare; documented limitation). Desk-paid packs: refund recorded + credits revoked in one transaction. Razorpay-paid packs: credits revoked when the pending refund is committed; a refused/failed provider refund reinstates them (compensating rows). Generic refund endpoints refuse pack invoices.
- **D14 PT consumption.** There is no PT appointment booking flow in the product, so a PT credit is spent by a staff "Record a PT session" action (appointment row `state=attended`, 1 credit, FIFO). Booking PT sessions in advance is out of scope.
- **D15 Media signing key** is derived from `SHARK_PASS_SECRET` (HMAC with a fixed label) rather than a new required secret. URLs are bound to one viewer, live 5 minutes, and the file route requires that viewer's session and re-checks access at serve time (403 forged/expired, 404 not allowed).
- **D16 Image handling without native deps.** Client: canvas re-encode to JPEG ≤ 2048 px (drops EXIF/GPS). Server: magic bytes, metadata stripped by copying image data verbatim (JPEG APPn except JFIF/Adobe + COM; PNG ancillary text/time/EXIF/pHYs; WebP EXIF/XMP + VP8X flags), > 4096 px refused (no server resize). `sharp` not added.
- **D17 Uploads in production** are off until `SHARK_MEDIA_DIR` is set (must not be under a web build); dev/test default to `media/` beside `SHARK_DB`. Quota: `tenants.quotas.storageMb` (seed 5000) else `SHARK_MEDIA_QUOTA_MB` (2048) → 429 `QUOTA_EXCEEDED`.
- **D18 Who sees photos.** Only the member and their assigned coach (visibility `coach`, consent granted, not scheduled for deletion). Owners/managers who are not the assigned coach see "shared only with the assigned coach" and nothing else; an unassigned trainer gets 404 on the member. Consent version 2.0; withdrawal hides immediately and schedules deletion after `photoRetentionDaysAfterWithdrawal` (tenant setting, default 30); re-consent before then cancels. Erasure destroys photos; the privacy export lists them (metadata + checksum, not bytes).
- **D19 Offline boot.** Found by the freestyle e2e: an offline reload signed the member out. Boot now keeps the last confirmed member session when the API is unreachable (cached viewer/branches, cleared on sign-out or a refused session) and re-checks on reconnect.
- **D20 Coaches and money.** Trainers see credit balances and history, not pack prices/invoices/refunds (server omits `packs`/`offers` without `billing.view`).
- **D21 Backups.** Manifest v2 adds a `media` section (archive checksum + every file's SHA-256); restore verifies each file before moving anything and refuses to overwrite a non-empty media dir without both flags. Dependency-free ustar writer/reader. Pilot scripts updated (compose `SHARK_MEDIA_DIR`, probe restores media into scratch, off-site encrypt/upload of the archive, drill restores + verifies media rows, pull-backup copies/verifies it; database checksum read from the top-level key only).
- **D22 e2e ports.** `SHARK_E2E_PORT` (and existing `SHARK_E2E_RAZORPAY_PORT`) pin ports; defaults unchanged (free port). This worktree ran with 18510/18511. `@mobile` specs run on the Pixel 7 project.
