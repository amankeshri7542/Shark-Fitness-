# P04: Installable member app (PWA + Android TWA), Web Push, and an installable staff console

## Summary

The member app is now a phone app on the Sonar design. It lives at `/app/`, installs with a complete manifest and icons, opens and shows the member's last-seen data with no network, and gets updates without interrupting a workout. It receives push notifications that open the exact screen. Signing out leaves nothing of the member on a shared phone. Saved preferences now take effect (theme, reduced motion, haptics, kg/lb). It lays out edge to edge on phones and in a centred column on tablets. It ships to Google Play as a Trusted Web Activity, built by a manual GitHub workflow. The staff console is installable on reception tablets, with a worker that caches only the shell. The decision is recorded as ADR-002: a PWA plus an Android TWA, with Expo deferred.

## What changed

### Member app (`apps/member-pwa`)
- **Base path `/app/`.** Vite base, router basepath and manifest scope moved. `lib/paths.ts` handles the prefix.
- **Service worker** (`src/sw/sw.ts`, injectManifest):
  - precaches the shell and the screens that work offline, with an `offline.html` fallback;
  - leaves the API network-only;
  - has push and notification-click handlers that open the exact deep link (`lib/push-payload.ts` keeps links inside `/app/`).
- **Updates** wait for permission (`registerType: 'prompt'`): `lib/sw-update.ts` and `ui/UpdateBar.tsx` show "Update ready / Reload" only when no workout is active.
- **Manifest** (`manifest.config.ts`):
  - `id`, `scope`, `start_url` `/app/?source=pwa`, `display_override` and categories;
  - icons: any 192/512, maskable 512, monochrome 96, plus a 180 apple-touch-icon;
  - three shortcuts and four real store screenshots;
  - iOS meta tags.
- **Icons** are all rendered from `icons/source.svg` by `pnpm -F @shark/member-pwa icons` (@resvg/resvg-js), for both apps.
- **Fonts** are self-hosted (latin subsets, OFL) and preloaded; Google Fonts is gone from both apps.
- **Offline read state** (`lib/persisted-cache.ts`):
  - an IndexedDB snapshot per `tenant:user`, kept 24 h, with a version buster;
  - holds only Home, the training plan, Book's list and consents; never the pass or billing;
  - the app can start offline from the last person's snapshot;
  - a banner reads "Offline — showing what was saved at HH:MM".
- **Session safety:**
  - Profile › Sign out warns about unsynced work ("3 workout sets haven't synced yet…", with Sign out anyway or Stay);
  - signing out wipes the query cache, the snapshot, this person's outbox, every `shark.workout*` key and the push device (`lib/session.ts`);
  - a global 401 handler shows "Your session ended", keeps the outbox and any active workout, and returns the same person to the same route;
  - a deletion request now really signs the phone out, as its copy says.
- **Preferences applied** (`lib/preferences.ts`):
  - theme with no flash (an inline boot script reads a device copy) and live "system" following;
  - reduced motion;
  - haptics (`navigator.vibrate`) on set logged, rest done, check-in and PR, only when the preference is on and the device supports it;
  - kg/lb across Workout, Summary, Progress, Train, Exercise and Home;
  - preference saves are optimistic and stored in the session store; the plan query now uses one key everywhere.
- **Navigation:**
  - header bell with an unread badge, mirrored to the Badging API;
  - Profile › More: Billing, Library, Messages, Install app, Help (a new screen);
  - Summary gets Done and Share.
- **Install:** `beforeinstallprompt` is always held back. "Install app" is in More, a one-time dismissible banner appears from the second visit, and iOS gets an Add-to-Home-Screen sheet.
- **Responsive:**
  - the 428×908 frame is gone;
  - safe areas on the header, nav, Pass, workout header, sheets and footers;
  - a 720 px column on tablets, with two-column Book and Progress;
  - 44 px header controls.
- **Push UI** (`ui/PushSettings.tsx`): a rationale first; the permission prompt only appears after "Allow notifications"; hidden when the server has no VAPID keys. The subscription is re-attached after a new sign-in.

### API (`apps/api`)
- **Config:** `SHARK_VAPID_PUBLIC_KEY`, `SHARK_VAPID_PRIVATE_KEY`, `SHARK_VAPID_SUBJECT` (all or none, shapes checked), `SHARK_PUSH_EXTRA_ENDPOINT_ORIGINS` (local fake services only), and `SHARK_ANDROID_PACKAGE` + `SHARK_ANDROID_CERT_SHA256` (fingerprint format validated at boot). `pnpm -F @shark/api vapid:keys` generates a key pair.
- **Migration `0018_push_notifications`:** `push_subscriptions` and `push_deliveries`, generated by drizzle-kit; drift check reports "No schema changes".
- **Routes:** `GET`/`POST /v1/me/push-subscriptions` and `DELETE /v1/me/push-subscriptions/:id`.
  - Endpoints must be on a browser push-service host (SSRF guard).
  - Switching push on records the new `push_notifications` consent purpose.
  - A re-registered endpoint moves to whoever registered it last.
- **Notification service** (`services/notifications.ts`, `services/push.ts`):
  - `notifyUser` writes the in-app row and a durable push delivery, and is safe inside `transact()`;
  - sending happens outside transactions with `web-push` and a 10 s `fetch`;
  - it honours consent, quiet hours in the branch timezone (with expiry) and dedupe keys;
  - 404/410 removes the device; failures retry up to 3 times;
  - only devices whose registering session is still live receive pushes;
  - a `deliver-push-queue` job runs every minute.
- **Wired notifications:** class reminder (the `class.tomorrow` automation), class cancelled or changed, waitlist offer, staff messages (says who wrote, never what), payment due (dunning) and payment received (settlement). `notifyPaymentOutcome` is the seam for P02.
- `/.well-known/assetlinks.json` is built from config, and returns 404 when unset.
- Members now get their own `attendance.checked_in` event on their member channel; before this they received none.
- Privacy erasure deletes the person's push devices and queued pushes.
- `.webmanifest` files are served as `application/manifest+json`.
- **Placeholder `/`:** redirects to `/app/` and serves a retiring `/sw.js` until the website (P03) lands.

## Decisions and assumptions
- **PWA + TWA, Expo deferred** (ADR-002): one codebase, the offline outbox already exists, and there is no device SDK here to verify a native build. Revisit triggers: HealthKit/Health Connect, NFC/wallet, background location/BLE doors, App Store listing. Migration path: Capacitor or Expo over `@shark/contracts`, `@shark/domain` and `@shark/design-tokens`.
- **The `/app/` move is done on this branch** because P03 runs in parallel. `/` is a placeholder marked as such, to be replaced by the website.
- **Precache 657 KiB:** the shell plus offline-useful screens. Online-only screens are cached the first time they open; offline, an unopened screen explains it needs a connection.
- **The persisted cache is our own small module,** not the TanStack persister, so per-person partitioning and wiping are guaranteed directly.
- **Units are converted on the client,** including server-written "N kg" text; storage stays kg.
- **Push:**
  - one consent purpose (`push_notifications`), granted by switching push on and withdrawable in Profile;
  - every category respects quiet hours, and is dropped if it would expire before they end;
  - message pushes never carry the message text;
  - web-push is pinned at 3.6.7 rather than the brand-new 4.0.
- **Check-in haptics** needed a member-channel event (added). Events replayed on reconnect never buzz.
- **The theme boot script is inline.** P06 must allow it by hash.
- **The TWA package id and host are placeholders.** The client picks the final package id once, because it can never change on Play.
- **Tests updated, not weakened:** E2E routes now use `/app/` (client-error reports `/app/train`). The admin recovery-link test asserts the `/app/` prefix. Two member unit-test `../api` mocks now spread the real module.
- **E2E fixes for real bugs found by the new specs:**
  - Book was wider than a 360 px phone;
  - the console worker answered `/admin/` from its cache;
  - members never received their own check-in event;
  - the sign-in redirect dropped activation fragments.

## Independent review

- **Major (fixed):**
  - An unfinished workout left by a 401 could be finished by the next person to sign in on the phone (`e6d39db`).
  - Signing out offline left the browser push subscription active (`421ddb5`).
  - A support operator impersonating a member could receive that member's pushes for the whole session lifetime, because delivery ignored the impersonation expiry (`1398e88`).

- **Minor (fixed):**
  - The app-icon badge survived sign-out (`3bbadca`).
  - A 401 racing the deletion request skipped the sign-out wipe (`ff4acad`).
